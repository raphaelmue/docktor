<objective>
Give the StackEvent audit trail a read path, and collapse its two write paths into one.

Purpose: UAT test 16 failed because the events were only ever half-built. `FileWatcher` writes them and the SSE broadcast fires, but nothing exposes them: `GET /api/stacks/:id` never includes them, no events route exists, and `StackEventRepository.findRecentByStack()` — built in plan 02-02 for exactly this — has never been called from anywhere. The write side has the mirror-image problem: the dedicated repository is bypassed in favour of an ad-hoc method bolted onto `StackRepository` that casts its way past the enum type.

Output: An authenticated events endpoint backed by the application service, and a single typed write path through the repository that owns the table.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> API | An authenticated browser session requests events for a stack id and a page size it supplies |
| compose file on disk -> StackEvent rows | Parser error text from a user-editable file is persisted as an event message and later served to the client |
| background job -> database | FileWatcher writes rows outside any request context |

| T-02-15-01 | Information Disclosure | GET /api/stacks/:id/events | high | mitigate | The plugin's `requireAuth` `onRequest` hook already covers every route it registers, including this one; the query is scoped to the single addressed stack id and returns no cross-stack data |
