<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server response -> React rendering | Tag strings originating in a third-party registry are rendered in the dialog |
| user interaction -> upgrade request | A click initiates a state-changing operation that rewrites a file on the host |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12-01 | Tampering | Registry-supplied tag strings rendered in the dialog | medium | mitigate | Candidates were already filtered server-side in plan 02-10 to values `semver.coerce` or `parseDateTag` accept, and React escapes text content by default; no `dangerouslySetInnerHTML` may be introduced in these components |
| T-02-12-02 | Elevation of Privilege | Upgrade triggered without deliberate user intent | high | mitigate | The upgrade fires only from an explicit dialog confirmation, never on open, on render, or on an SSE event; the trigger is disabled during transitional states. The server route independently enforces `requireAuth` and `guardTransition` |
| T-02-12-03 | Information Disclosure | Error text surfaced in the dialog | medium | mitigate | Only the `ApiError` message is rendered; raw server stack traces are not exposed by the existing global error handler, and no additional detail is requested here |
| T-02-12-04 | Spoofing | Path segments built from a service name | medium | mitigate | Both new API client functions encode the stack id and service name with `encodeURIComponent`, and the server resolves the service within the addressed stack only |
| T-02-12-05 | Denial of Service | Repeated tag fetches from an open dialog | low | mitigate | The dialog fetches once per open with no polling and no refetch on re-render; the endpoint serves persisted data and never reaches the registry |
| T-02-12-06 | Tampering | npm/yarn installs | high | mitigate | No new dependencies — the `Dialog` and `Select` primitives and `sonner` are already present. `yarn.lock` must be unchanged; if an install seems necessary, stop and request a package legitimacy audit |
</threat_model>
