## What was actually wrong (verified 2026-08-27, supersedes the UAT diagnosis)

The UAT `missing` items for Gap 4 were "add diagnostic logging" and "improve the error message". Both are already done — do not redo them. Re-reading the current source turned up these four real defects:

1. **`manifestInspect()` hardcodes `latestTag: null`** (`docker-executor.ts:104`). Because of that, the branch `if (latestTag && tag !== "latest")` at `update-checker.ts:295` can never be entered, so the semver/date comparison that UPD-01 specifies is unreachable dead code in production. Every image silently falls through to the digest branch. **Deferred to plan 02-10**, which adds the registry tag listing that this needs.

2. **`currentDigest` is never written.** `ImageUpdateCheck.currentDigest` exists in the schema and `ImageUpdateCheckRepository.upsert()` accepts it, but the `UpdateCheckerRepo.upsertImageUpdateCheck` input type at `update-checker.ts:136-143` omits the field and `checkImage()` never passes it — while `checkImage()` *reads* `existing?.currentDigest` at line 298. It is therefore permanently null, exactly as the user reported. Fixed here, Task 1.

3. **The digest branch cannot fire on a first check.** `update-checker.ts:302-306` sets `hasUpdate = prevDigest !== null && prevDigest !== latestDigest`, comparing the registry digest against *the previously observed registry digest*. That answers "did the registry change since we last looked", not "does the registry differ from what we run". A correct first check is impossible by construction. Fixed here, Task 1.

4. **The badge join key does not match the stored key.** `routes/stacks.ts:38` and `:46` build the lookup key as `normalizeImageRef(s.image)`, but `Service.image` holds the image *without* its tag (`parseImage()` splits them). For a service on `nginx:1.25` the route looks up `nginx:latest` while the UpdateChecker stored `nginx:1.25`. The map lookup misses, so `updateAvailable` is always false regardless of detection. Fixed here, Task 3.

A fifth, lower-severity defect: `const tag = imageRef.split(":")[1] ?? "latest"` (`update-checker.ts:291`) splits on the first colon, which is the port separator for a ref like `registry.example.com:5000/app:1.2`. Fixed here, Task 2.
</gap_status_findings>
