<objective>
Give the UpdateChecker a real tag list so that `latestTag` stops being hardcoded null, and persist that list so the version-selection UI in plan 02-12 has something to offer.

Purpose: This is the fourth and deepest defect behind UAT Gap 4. `manifestInspect()` returns `{digest, latestTag: null}` by construction — `.planning/debug/manifest-inspect-null.md` (evidence entry 00:06) traced this to a deliberate choice recorded in 02-04-PLAN.md line 396, on the grounds that tag listing needs a separate registry API. The consequence is that `if (latestTag && tag !== "latest")` in `checkImage` is unreachable, so the semver and date-tag comparison that requirement UPD-01 specifies has never run in production. 02-RESEARCH.md Open Question 3 flagged exactly this and deferred the decision to planning. It is resolved here as in scope: UAT gap 5 asks for a user-selectable upgrade target, which cannot exist without a tag list.

Output: A `RegistryClient` that lists tags over the standard Registry v2 API, candidate-selection logic, persistence of the candidates, and a read-only route serving them.
</objective>

  <action>
Create `server/src/infrastructure/registry-client.ts` holding a `RegistryClient` class with a single public method `listTags(imageRef)` typed `Promise<string[] | null>`, plus a `registryClient` singleton export at the foot of the file mirroring how `dockerExecutor` is exported.

Derive the target from the image reference rather than re-parsing it: call `splitImageRef` (added by plan 02-09) to drop the tag, then determine the registry host. When the name has no slash, or its first path segment contains no dot and is not `localhost`, the image lives on Docker Hub: the request host is `registry-1.docker.io` and a single-segment name is prefixed with `library/`. Otherwise the first path segment is the host and the remainder is the repository path. Request `https://{host}/v2/{repository}/tags/list?n=100`. Implement the standard token challenge: on a 401, read the `WWW-Authenticate` response header, parse its `realm`, `service` and `scope` parameters, GET the realm with `service` and `scope` as query parameters, take `token` or `access_token` from the JSON body, and retry the original request once with an `Authorization` bearer header. Retry at most once — a second 401 throws.

Security constraints that are not optional. Force the scheme to HTTPS and reject any derived host that is not a syntactically valid host, so a crafted compose file cannot steer the request at an internal address over plaintext. Pass `redirect: "error"` (or explicitly validate that any followed location keeps both the HTTPS scheme and the same host) so the registry cannot bounce the authenticated request elsewhere. Set an `AbortSignal.timeout` of 15 seconds on every request. Cap the response body: read it as text and abandon with a warn log past roughly 2 MB before attempting to parse, so a hostile registry cannot exhaust memory. Never attach a token obtained from one realm to a request against a different host.

Map outcomes as described in the behavior block. Define and export `RegistryUnavailableError` in this file as a subclass of the project's `AppError` base from `../lib/errors.js`, preserving the original error in `cause` per the CLAUDE.md rule for wrapping infrastructure errors. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| compose file -> outbound HTTP target | An image reference authored by a host operator determines which remote host the server contacts — the sharpest boundary in this plan |
| registry -> server | Registry-controlled JSON, headers and redirects are parsed by the server |
| browser -> tags route | An authenticated user supplies a stack id and a service name |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-10-01 | Information Disclosure | `RegistryClient.listTags()` server-side request forgery | high | mitigate | The scheme is forced to HTTPS, the host is derived only from the image reference, redirects are refused or constrained to the same host and scheme, and a bearer token obtained from one realm is never replayed to a different host. A compose file naming an internal address cannot elicit a plaintext request to it |
| T-02-10-02 | Denial of Service | Hostile or huge registry response | high | mitigate | Every request carries a 15-second `AbortSignal.timeout`, the tags query is bounded with `n=100`, and the response body is abandoned past roughly 2 MB before parsing |
| T-02-10-03 | Elevation of Privilege | `GET /api/stacks/:id/services/:serviceName/tags` | high | mitigate | The route is behind `requireAuth`, and the service is resolved from the addressed stack's own service list so a guessed service name cannot reach another stack's data; a miss returns `NotFoundError` |
