<objective>
Show the user the audit trail that has been recorded all along.

Purpose: UAT test 16 failed with "I dont see no config_changed in the Status Log. Only in the server logs." The card the user was reading renders `StatusLog` — stack status transitions — which is a different Prisma model that merely has a similar name. The `StackEvent` audit trail had no read path at all until plan 02-15 added one. This plan consumes that endpoint and gives the events their own clearly labelled place in the UI, next to the status log rather than blended into it, so the near-identical naming stops misleading the reader.

Output: An API client function, a hook that keeps the log live over SSE, an Event Log card, the Status Log card extracted out of the page file so the two sit side by side as peers, and tests for both the hook and the card.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server response -> React rendering | Event messages and payloads originating in user-edited compose files and third-party registry data are rendered in the page |
| SSE stream -> client state | Server-pushed events drive refetches in an authenticated browser session |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-16-01 | Tampering | Event message and payload text rendered in the card | medium | mitigate | React escapes text content by default and no `dangerouslySetInnerHTML` may be introduced in these components; the payload is parsed with `JSON.parse` inside a try/catch and only known fields are read from the result |
| T-02-16-02 | Denial of Service | Refetch storm from a chatty stack | medium | mitigate | The hook refetches only on the three audit event types for the addressed stack id, one request per event, with no polling and no refetch on re-render; the endpoint caps its page size server-side |
| T-02-16-03 | Information Disclosure | Config error text shown in the UI | low | accept | The text is a YAML validation message about a file the authenticated user already owns and can read through the compose tab |
| T-02-16-04 | Spoofing | Stack id used to build the request path | medium | mitigate | The path segment is encoded with `encodeURIComponent`, and the server resolves the stack and scopes the query to that id (plan 02-15) |
| T-02-16-05 | Denial of Service | Unbounded rendering of entries | low | mitigate | The server caps and defaults the page size, and the card renders inside a fixed-height scroll area like its siblings |
| T-02-16-06 | Tampering | npm/yarn installs | high | mitigate | No new dependencies — `Card`, `Badge` and `ScrollArea` already exist. `yarn.lock` must be unchanged; if an install appears necessary, stop and request a package legitimacy audit |
</threat_model>
