<objective>
Make "Update Images" tell the truth when there was nothing to update.

Purpose: UAT test 11 failed because `updateImages()` infers "nothing changed" by lowercasing the `docker compose pull` output and searching it for phrases that the modern Compose CLI never emits. The debug session traced this to Compose's own source: a successful pull reports `Pulled` whether or not layers moved, and a skipped pull reports a `Skipped:` reason — so the up-to-date branch is effectively unreachable and the user is always told images were updated. This plan replaces the text scrape with the signal the update checker already relies on: the locally resolved image digest, read before and after the pull.

Output: A pure domain module for the comparison, a rewritten decision inside `updateImages()`, and the unit coverage for the true branch that was missing when the bug shipped.
</objective>

Create `server/src/domain/image-update-detection.ts` as a pure module: no imports from repositories, infrastructure, jobs or Prisma, and no I/O of any kind.

Export `ImageDigestComparison` with the readonly members `ref`, `before` and `after`, where the two digest members are `string | null` because the local image store legitimately has no digest for an image that is absent or was built locally.

Export `toImageRef(service: {image: string | null; imageTag: string | null}): string | null`. Return null when there is no non-blank image, so build-only services are excluded rather than turned into refs that can never resolve. Otherwise join the image and tag, default a missing tag to the same default Docker itself applies, and strip the redundant registry prefixes exactly the way `normalizeImageRef` in `jobs/update-checker.ts` does. Duplicate that small normalisation here rather than importing it: the domain layer must not depend on `jobs/`, and pulling that module in would drag node-cron, semver and the registry singleton into the application unit-test module graph. Head the function with a comment that names `jobs/update-checker.ts` as the other copy and points at the parity test below as the guard against drift — this mirrors the precedent and reasoning already documented at the top of `infrastructure/registry-client.ts`.

Export `detectNoUpdates(comparisons: readonly ImageDigestComparison[]): boolean`. Return true only on positive evidence: the list is non-empty and every entry has a non-empty string `before` that strictly equals its `after`. Every other shape — an empty list, any null or empty digest on either side, any inequality — returns false. Document why the bias runs this way: telling a user nothing changed when something did is the failure being fixed, so an unknown must fall back to the generic success message rather than the confident one.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| compose file on disk -> server process | Image names and tags originate in a file a user may edit over SSH and are used to build Docker CLI arguments |
| Docker CLI output -> server decision logic | Command output crosses into a branch that decides what the user is told |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-13-01 | Tampering | Image refs built from compose content and passed to the Docker CLI | medium | mitigate | Refs are passed as discrete `execFile` arguments by the existing `imageDigest()`, never through a shell, so a crafted image string cannot inject a command; refs that are blank are dropped before any call |
| T-02-13-02 | Spoofing | Deciding "nothing changed" from CLI progress text | medium | mitigate | The decision moves to the content-addressed local image digest, which the CLI does not render as free text and which an unstable output format cannot forge; this is the gap being closed |
| T-02-13-03 | Denial of Service | Extra Docker calls per update run | low | accept | `imageDigest()` reads only the local image store and makes no network call, so registry rate limit (UPD-02) is untouched; two local inspects per service on a user-initiated action is proportionate |
| T-02-13-04 | Denial of Service | A stack stranded in UPDATING by a throw in the new code | high | mitigate | Ref collection runs before the transition and is total; digest snapshots cannot throw; Task 2 covers each degraded path with a test asserting a non-transitional final status |
| T-02-13-05 | Information Disclosure | Digest values in logs | low | accept | Digests are public content addresses of public images and carry no secret; only warnings on absence are logged |
| T-02-13-06 | Tampering | npm/yarn installs | high | mitigate | No new dependencies; `yarn.lock` must be unchanged. If an install appears necessary, stop and request a package legitimacy audit |
</threat_model>
