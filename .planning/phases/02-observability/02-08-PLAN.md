<objective>
Restore the compose-to-database service metadata sync in FileWatcher, in a form that does not destroy container runtime state — the defect that caused the previous fix to be reverted.

Purpose: UAT Gap 1 (major, test 4) is the only gap of the six that is unambiguously still broken, and it regressed. Plan 02-06 added `replaceServices()` to `handleFileChange()` (commit `2d63718`). Commit `b815e4c` ("fixed bugs", 2026-03-17) reverted it and left a comment asserting service records must reflect what is running rather than what is in the compose file. That concern is legitimate — `StackRepository.replaceServices()` is a `deleteMany` + `createMany` transaction, so wiring it into FileWatcher blanks `containerId`, `containerState`, `healthStatus`, `restartCount` and `imageDigest` on every external compose edit. The fix is not to re-apply the revert, it is to add a sync that updates config-derived columns only.

Output: A `syncServicesFromCompose()` repository method, FileWatcher wired to it, a compose-parser hardening for sequence-valued `services`, and unit tests covering both.
</objective>
