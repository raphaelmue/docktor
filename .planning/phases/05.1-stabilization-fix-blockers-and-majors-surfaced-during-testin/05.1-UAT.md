Confirmed root cause via `docker compose config`: docker-compose.yml's `environment: DOCKTOR_STACKS_DIR: ${DOCKTOR_STACKS_HOST_DIR:-/opt/docktor/stacks}` and the matching volume line are resolved by Compose's own variable interpolation, which only reads a file literally named `.env` (or `--env-file`/shell env) — NOT `.env.local`. `env_file: .env.local` only injects vars into the container's runtime environment, so the app process sees the real custom DOCKTOR_STACKS_HOST_DIR while Compose-time interpolation silently fell back to the /opt/docktor/stacks default for DOCKTOR_STACKS_DIR and the volume host side. This affects ANY non-default DOCKTOR_STACKS_HOST_DIR set per docs/deployment.md, not just Windows paths — not a UAT test-list item, a defect discovered during Test 3 while investigating an unrelated report."
