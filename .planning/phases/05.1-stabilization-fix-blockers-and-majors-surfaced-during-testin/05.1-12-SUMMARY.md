# Phase 05.1 Plan 12: Windows Scan Path Separator Gap Closure Summary

**Normalized `BrownfieldScanner.scan()`'s fast-glob output to OS-native separators at a single boundary call, plus a `directoryDisplayName()` client helper so no consumer of the now-native paths regresses (G-05.1-4).**

## Accomplishments
- `BrownfieldScanner.scan()` now normalizes every fast-glob result to the host OS's native path separator at the single point it enters `foundFiles`, before `path`/`directory` are derived and before the Set-based dedup — fixing both fields from one call and making dedup canonical-spelling-aware
- A new Windows-shaped regression test (`brownfield-scanner-windows-paths.test.ts`) mocks `node:path` to `win32` for its whole module graph and proves the fix catches a reintroduction from a Linux CI runner, with no native Windows machine required
- New `directoryDisplayName()` pure client helper extracts a trailing folder name tolerant of POSIX, Windows, drive-qualified, and mixed-separator paths, replacing three forward-slash-only `.split("/").pop()` call sites across `brownfield-import.tsx` and `migration-wizard.tsx`

## Decisions Made
- Normalize at the fast-glob boundary (`foundFiles.push`), not at the `path`/`directory` field-derivation lines — a single call site covers both fields and canonicalizes spelling ahead of dedup, per the plan's explicit design note
- `directoryDisplayName()` placed in a new `client/src/lib/path-display.ts`, kept free of imports as a pure string utility, per the plan's instruction not to put it in `utils.ts` (the shadcn `cn()` module)
- Bare-root detection implemented as: strip trailing separators, then match the remainder against `/^[A-Za-z]:$/` for a Windows drive root (POSIX root reduces to `""` naturally). This correctly distinguishes `"C:\\"` (root, `""`) from `"C:\\myapp"` (`"myapp"`) without special-casing the POSIX case separately
