# Phase 05.1 Plan 11: Application-owned stacks directory creation Summary

**Added `ensureStacksDir()` to `lib/stacks-dir.ts` and wired it into the server boot sequence so the managed stacks directory is created by the application itself rather than relying on Docker's legacy, Desktop-divergent bind-mount auto-creation — closing gap G-05.1-3.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 2
- **Files modified:** 4 (3 modified, 1 created)

## Accomplishments
- `ensureStacksDir()`: recursive, idempotent `mkdir` on the resolved stacks path, with a doc comment explaining why the app must not depend on Docker's bind-mount auto-creation (legacy/best-effort for short-syntax mounts, and materially different on Docker Desktop's WSL2 backend vs. native Linux dockerd)
- Failure path rethrows a new `Error` (with `cause` preserving the original) naming the exact path and the two operator-checkable causes, matching the tone of the existing `assertStacksDirMatchesHost()` error
- `server/src/index.ts` now calls `assertStacksDirMatchesHost()` then `await ensureStacksDir()` inside the same fail-fast `try/catch`, before `syncDatabaseSchema()`/`buildApp()`/`listen()`
- Unit test suite extended with 4 new tests against a real `mkdtemp` filesystem (no module mocking): nested-absent creation, idempotency-with-existing-content, path parity with `getStacksDir()`, and error-rethrow on an unwritable target
- Filed `.planning/todos/pending/2026-09-03-stacks-dir-mount-point-not-verified.md` (`[major]`) recording the deliberately deferred, more severe failure mode: `mkdir` alone cannot prove the created directory is the host-backed bind mount rather than a plain directory in the container's own writable layer

## Decisions Made
- Logic placed in `lib/stacks-dir.ts` (not inline `fs.mkdir` in `index.ts`), per the plan's explicit design note — keeps `index.ts` a thin sequence and makes the behavior unit-testable
- Startup order kept strict: assertion before creation, so a configuration mismatch is caught before any directory gets materialized at a path already known to be wrong
- Deferred the mount-point-vs-writable-layer distinction to a filed todo rather than building a `/proc/mounts` check here — out of scope per the plan, and `mkdir` alone fully satisfies G-05.1-3's stated truth criterion
