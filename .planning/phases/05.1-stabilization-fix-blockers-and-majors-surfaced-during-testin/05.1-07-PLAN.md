<objective>
Give brownfield import/adopt a reachable home after the setup wizard closes (todo item M6), by exposing the existing scan/adopt/migrate capability through its own authenticated routes and a Stacks-page entry point.

Purpose: `BF-01` through `BF-05` are all implemented, but the only place that renders `BrownfieldStep` is `client/src/routes/setup.tsx`. Once the wizard finishes, the whole capability is unreachable — and it cannot simply be re-linked, because Phase 05's T-05-09 correctly makes every `/api/setup/*` route beyond `/status` and `/step1` return 410 the moment the wizard is complete. The feature therefore needs authenticated routes of its own.
Output: `server/src/routes/imports.ts` behind `requireAuth`, a shared `BrownfieldImport` component used by both the wizard and a new `/stacks/import` page, and an "Import Existing Stack" action on the Stacks page.

Security note: the original form of this todo was filed as a blocker because `/api/setup/scan` and `/api/setup/adopt` were reachable by any unauthenticated caller forever. Phase 05's T-05-09 closed that. **Task 1 re-verifies that gate against the running code rather than trusting the note**, and the new routes must not reintroduce the same hole under a different path.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated internet -> `/api/stacks/import/*` | the new routes are the exact capability that was, until Phase 05's T-05-09, reachable without a session on `/api/setup/*` |
| authenticated request body -> host filesystem | `directories` and `composePath` are caller-supplied absolute paths that the scanner and adopter read |
| Docktor container -> host root | `docker-compose.yml` mounts `/:/host:ro`, so the scanner's reach is the entire host filesystem |
| discovered file content -> the browser | scanned compose files' service names, images and paths are rendered in the results table |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05.1-32 | Spoofing / Elevation of Privilege | the four new `/api/stacks/import/*` routes | high | mitigate | Task 1: `app.addHook("onRequest", requireAuth)` as the plugin's first statement, plus an integration test asserting an unauthenticated request to each of the four endpoints is rejected. This is a direct regression guard against the original filed blocker |

An accidental match would silently make every new endpoint public |

Additionally, verify and record what `BrownfieldScanner.scan()` already refuses to traverse — the wizard UI advertises that `/proc`, `/sys` and `/dev` are excluded, so confirm the server enforces that rather than the client merely claiming it. If the exclusion turns out to be client-side only, implement it server-side in this task |
| T-05.1-35 | Tampering | `adoptInPlace(composePath, displayName)` accepting an arbitrary path | high | mitigate | Adoption registers an arbitrary host directory as a managed stack, after which Docktor will run `docker compose` in it.
