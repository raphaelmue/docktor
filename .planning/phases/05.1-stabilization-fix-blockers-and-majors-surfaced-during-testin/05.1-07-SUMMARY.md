# Phase 05.1 Plan 07: Post-setup brownfield import Summary

**Brownfield scan/adopt/migrate is now reachable after setup via `requireAuth`-gated `/api/stacks/import/*` routes and a shared `BrownfieldImport` component driving both the wizard and a new `/stacks/import` page.**

## Performance

- **Duration:** ~45min
- **Completed:** 2026-09-02
- **Tasks:** 3 completed
- **Files modified:** 14 (7 created, 7 modified/renamed)

## Accomplishments

- `server/src/routes/imports.ts`: a new `FastifyPluginAsyncZod` behind `app.addHook("onRequest", requireAuth)` exposing `POST /api/stacks/import/{scan,adopt,migrate/preview,migrate}`, delegating straight to the existing `brownfieldScanner`, `onboardingService.adoptInPlace()`, and `migrationService` — no reimplementation, no duplicated Zod schema (`wizardStep5Schema` reused for the scan body). `server/src/routes/setup.ts` is byte-for-byte unchanged.
- Verified the new `/api/stacks/import` prefix is not accidentally covered by `app.ts`'s first-run `onRequest` exemption (which matches only the exact `/api/setup/` and `/api/auth/` prefixes) — the exemption cannot silently make the new routes public.
- Extracted the wizard's brownfield UI into `client/src/components/domain/stack/brownfield-import.tsx`, a shared `BrownfieldImport` component that takes its four API functions (`scanDirectories`, `adoptStack`, `previewMigration`, `executeMigration`) as an injected prop object instead of importing `setup-api.ts` or `import-api.ts` directly — the same component now drives both the wizard (`brownfield-step.tsx`, wired to `setup-api.ts`) and the new post-setup page (wired to the new `import-api.ts`).
- Moved the five shared DTOs (`DiscoveredStack`, `ScanResult`, `VolumeSelection`, `MigrationPreview`, `MigrationResult`) into a neutral `client/src/lib/brownfield-types.ts`; `setup-api.ts`, `import-api.ts`, and `migration-wizard.tsx` all import from there.
- Added `client/src/routes/app/stacks/import.tsx` (48 lines — inside the plan's 80-line budget) at `/stacks/import` inside the protected route block, and a secondary "Import Existing Stack" action (with a `FolderInput` icon) on the Stacks page header next to the existing primary "Create Stack" action.
- `server/test/integration/imports.test.ts` (new) covers 401 rejection for all four endpoints, a real scan+adopt round trip (asserting the `slugify()` guarantee — `"My Imported App"` -> `"my-imported-app"`, T-05.1-35), and a direct regression guard proving `/api/setup/scan` and `/api/setup/adopt` still 410 once the wizard is complete while the new routes keep working (T-05.1-36).
- `client/test/integration/stacks-import.spec.ts` (new) covers the Stacks-page entry point and a scan->adopt flow through `/api/stacks/import/*`. Full client Playwright suite: **71/71 passing**, including all 21 `setup-wizard.spec.ts` tests unchanged by the extraction.
