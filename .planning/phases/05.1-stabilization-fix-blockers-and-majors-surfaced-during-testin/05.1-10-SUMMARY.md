## Accomplishments

- `docker-compose.yml`'s two `env_file:` entries (`docktor`, `db`) now point at `.env` instead of `.env.local` — the file Docker Compose actually auto-discovers for top-level `${VAR}` interpolation. Verified live: rendering the compose file in an isolated directory with a custom `DOCKTOR_STACKS_HOST_DIR` in `.env` and a plain `docker compose config` (no flags) now correctly propagates that value to `DOCKTOR_STACKS_DIR` and to both sides of the stacks bind mount.
- Extended the `environment:` block's inline comment explaining *why* the filename must not change: interpolation and `env_file:` are structurally different mechanisms, and only a file literally named `.env` feeds the former.
- Added a root-anchored `.dockerignore` (`/.env`, `/.env.local`, `/.env.production`, `/.git`, `/.planning`) so the `docktor` service's `build: context: .` no longer uploads the operator's filled-in secrets (`DATABASE_URL`, `BETTER_AUTH_SECRET`, `ENCRYPTION_KEY`, `POSTGRES_PASSWORD`) to the Docker daemon on every `docker compose up -d` (T-05.1-46). Confirmed it excludes nothing the Dockerfile's `COPY` lines reference, and that the tracked `.env.example` template stays in context.
- Rewrote every `.env.local` reference in `docs/deployment.md` and `README.md` to `.env`: the Quickstart copy command and callout, the environment-variable table, the stacks-directory section, the database-schema opt-out sentence, and troubleshooting rows 1/2/4.
- Added a callout immediately after the Quickstart copy command explaining the filename is load-bearing, not a convention, and why a rename silently breaks the stacks mount.
- Added troubleshooting row 9 for operators upgrading an existing installation: symptom, cause, and a `mv .env.local .env` fix — no values need editing.
- Reworded the ambiguous "no missing `.env` values" closing sentence in Quickstart step 3 to "no missing environment variable values", now that `.env` unambiguously refers to the actual filename elsewhere in the doc.
