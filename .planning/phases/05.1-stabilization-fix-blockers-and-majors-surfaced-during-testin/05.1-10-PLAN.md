<objective>
Close gap **G-05.1-2**: following the documented quickstart with any non-default `DOCKTOR_STACKS_HOST_DIR` makes the server refuse to boot with a stacks-directory path mismatch. This blocked UAT tests 3, 4 and 5 outright.

The defect is not in the assertion — the assertion is correct and caught a real misconfiguration. Docker Compose resolves top-level `${VAR}` interpolation only from the real process environment or a project-root file named exactly `.env`; it never reads a service-level `env_file:` directive. The documented workflow puts the operator's value somewhere interpolation cannot see, so `DOCKTOR_STACKS_DIR` and **both sides of the stacks bind mount** silently fall back to their hardcoded defaults while the container's runtime environment gets the real custom value. Even with the assertion removed, the mount itself would still point at the wrong host directory — the crash is the app correctly refusing to run in a state that would silently misplace stack data.

Purpose: this is the second time in this phase the same Compose interpolation-vs-`env_file` distinction has produced a shipped bug — WR-04 hit it for `POSTGRES_PASSWORD` and worked around it by removing that variable's need for interpolation. That workaround does not transfer here: a `volumes:` bind-mount source is part of the container spec Compose builds *before* any container process exists, so `env_file:` structurally cannot reach it. The durable fix is to make the file operators are told to create be the file Compose already auto-discovers, and to say so at the point of instruction.

Output: a compose file, a `.dockerignore`, and documentation that describe one env file, loaded by one mechanism, with no flag required on any `docker compose` invocation.

**Decomposition shape:** horizontal, not tracer-first (`--no-tracer` reasoning). Nothing architectural is being proven; this is a rename of one load-bearing identifier across its consumers plus the documentation that names it. Task 1 carries the real behavioral proof.

**Deliberately rejected alternatives** (both are recorded in the diagnosis; do not implement either):
- Keeping the old filename and adding an explicit env-file flag to every documented command. Any future operator, script, or doc that runs a bare `docker compose` command silently reintroduces this exact failure, and the two-mechanism split remains a standing trap.
- Restructuring the compose file to avoid interpolation for the volume. Not achievable — `env_file:` cannot populate a `volumes:` entry.
</objective>
