<objective>
Cut Docktor's database schema management over from schemaless synchronisation to real Prisma migrations, for v1.0.0 — and make an existing self-hosted install upgrade into it without the operator doing anything.

This is the tracer slice for scope item 2: it wires one path end to end — generate the baseline migration, apply it through the boot sequence's existing guarded step, and prove it against a live database — rather than landing the schema work, the runtime work, and the documentation separately and discovering at the end that they disagree. Plan 09-04 expands outward from this proven slice into the image, the startup logging, and the deployment guide.

Purpose: `prisma db push` has no history, no review surface, and no rollback story. Shipping v1.0.0 on it means the first schema change after release has no defined way to reach an existing install. D-02 makes the v1.0.0 release the trigger to fix that, superseding the earlier "as late as possible" position recorded in STATE.md.

Output: a generated `0_init` baseline, a startup step that applies migrations instead of pushing a schema, automatic zero-touch baselining for already-synced databases with a loud drift probe behind it, and live confirmation that the command's real no-op output matches what the code classifies.
</objective>
