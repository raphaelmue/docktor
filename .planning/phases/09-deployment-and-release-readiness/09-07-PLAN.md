<objective>
Make the certificate source actually govern behaviour: stop ACME from ever touching a domain whose certificate the user supplied, and start watching those certificates for expiry.

Plan 09-05 added the field and plan 09-06 made certificates real. Nothing reads the field yet. Right now every TLS-enabled proxy configuration still gets an ACME issuance environment variable written into its compose file, which means uploading a certificate for a domain would produce exactly the wrong outcome: acme-companion would keep trying to issue one anyway. And the certificate poller would classify the domain by tailing the ACME container's log for a process that is not running, leaving a perfectly valid certificate showing as pending forever.

Purpose: a user-supplied certificate has no automatic renewal. Silence about an approaching expiry is a real outage waiting to happen, which is why D-13 requires a visible warning rather than letting the certificate simply stop working one morning.

Output: one function computing the issuance variable from the certificate-source field for both branches, a poller that classifies custom-sourced rows by file presence and expiry rather than by log archaeology, and an expiry warning travelling the live status stream that already exists.

**Tracer note:** scope item 4's tracer was plan 09-06's single upload path. This plan is horizontal expansion from that proven slice into the two existing subsystems that must now read the field, so it carries no tracer task of its own.
</objective>
