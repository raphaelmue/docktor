## Interaction Patterns

| Interaction | Pattern | Behavioral Contract |
|-------------|---------|---------------------|
| **Wizard navigation** | Linear stepper with clickable steps | User can click any completed or in-progress step in the stepper to jump back. Cannot skip ahead to future steps without completing current step. "Next" button validates current step before advancing. "Back" button always available (steps 2-5). |
| **Wizard step validation** | Inline validation on blur + submit validation | Required fields show error message below input on blur if empty. "Next" button triggers full form validation for current step; disabled state not used (validation feedback via errors only). |
| **Optional step skip** | "Skip" button on steps 3-5 | Clicking "Skip" advances to next step without saving any data from current step. No confirmation dialog (skipping is reversible — user can return via stepper). |
| **Volume checklist** | Checkboxes with default checked state | All named volumes and relative bind mounts default to checked (will be copied). User unchecks items to exclude from migration. Absolute paths default to unchecked with warning badge. |
| **Diff preview approval** | Read-only diff with explicit confirmation | User cannot edit diff directly. "Back" button returns to volume selection (step 1) to adjust choices. "Confirm & Migrate" button is primary destructive action (uses default primary styling, not destructive variant, since rollback is automatic). |
| **Background migration** | Fire-and-forget with toast notifications | Migration starts immediately on "Confirm & Migrate" click. User is returned to scan results page (or dashboard if navigated away). Toast shows progress: "Migrating..." → "Complete!" or "Failed — rollback complete". No blocking modal. |
| **Post-migration cleanup** | Two-step confirmation for destructive action | After successful migration, modal appears with "Keep Files" (safe default, closes modal) or "Delete Old Files" (opens secondary confirmation). Delete confirmation requires typed stack name (Phase 4 restore pattern). |
| **Scan directory input** | Multiple text inputs for directory paths | User enters one or more directory paths to scan (comma-separated or separate input fields). Default suggestions shown: `/home`, `/opt`, `/srv`. Validation: paths must be absolute and exist (backend validates). |
| **Compatibility badge tooltip** | Hover or tap to reveal explanation | Badge has `title` attribute for native tooltip on desktop. Mobile: consider click-to-reveal via Tooltip component from shadcn (wraps badge in TooltipTrigger). |
| **Setup already complete page** | Static message with link | If user visits `/setup` after wizard completion, show centered Card with heading "Setup Complete", description, and "Go to Dashboard" button. No wizard UI rendered. |

**Accessibility notes:**
- Wizard stepper: Use `aria-label` on step indicators (e.g., "Step 1: Create Admin Account"). Active step has `aria-current="step"`.
- Volume checklist: Group checkboxes in `<fieldset>` with `<legend>` for screen reader context.
- Diff viewer: Ensure sufficient color contrast for diff highlighting (not relying on color alone — use +/- symbols or background patterns).
- Background migration: `aria-live="polite"` region for toast notifications ensures screen reader announces completion.

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | button, card, input, label, select, popover, command, table, badge, alert, alert-dialog, tooltip, separator, skeleton, tabs | not required (official registry trusted) |
| shadcn official (to be added) | checkbox | not required (official registry trusted) |
| Community registry (TBD) | stepper (if using third-party) | **Required:** `npx shadcn view stepper --registry [url]` must be reviewed before installation. Developer must approve flagged patterns (network access, dynamic code execution, obfuscated code). |

**Stepper component decision:**
- **Option 1:** Build custom stepper component (recommended for full control and zero third-party risk). Estimated effort: 2-3 hours for numbered stepper with active/completed/inactive states.
- **Option 2:** Use community registry stepper (e.g., from shadcn-ui-expansions or cult-ui). **Must complete safety vetting gate before installation.** Review checklist:
  - [ ] No `fetch()`, `XMLHttpRequest`, or `navigator.sendBeacon` calls
  - [ ] No `process.env` access
  - [ ] No `eval()`, `Function()`, or dynamic imports from external URLs
  - [ ] No single-character variable names in non-minified source (obfuscation flag)
  - [ ] Source code readable and aligned with project quality standards

**If third-party stepper is used:**
- Record Safety Gate column entry: `view passed — no flags — 2026-04-08` OR `developer-approved after review — 2026-04-08 — [specific flags noted]`
- If vetting gate reveals unacceptable risk, fall back to custom stepper implementation.
