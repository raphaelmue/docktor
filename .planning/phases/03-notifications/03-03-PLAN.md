    Create `server/src/jobs/notification-watcher.ts` following the established job pattern (class + constructor DI + singleton export).

    The class must implement:

    **Constructor injection:**
    ```typescript
    interface NotificationWatcherDeps {
        notificationService: { notify(event: NotificationEvent): Promise<void> }
        broadcaster: { subscribe(handler: (event: StateEvent) => void): () => void }
        stackRepo: { findByIdOrThrow(id: string): Promise<{displayName: string; status: string}> }
        getRecentLogs?: (stackId: string) => Promise<string>
    }
    ```

    **State tracking (in-process Maps):**
    - `activeIncidents: Map<string, Set<string>>` — tracks stackId -> Set of active trigger types ("error" | "unhealthy")
    - `unhealthyTimers: Map<string, NodeJS.Timeout>` — tracks stackId -> pending UNHEALTHY grace timer
    - `unsubscribe: (() => void) | null` — stores broadcaster unsubscribe function

    **start() method:**
    1. Subscribe to `broadcaster` events
    2. On startup, query DB for stacks currently in ERROR or UNHEALTHY status to pre-populate `activeIncidents` (prevents duplicate notifications after server restart, per Pitfall 6 in RESEARCH.md)
    3. Store unsubscribe function

    **handleStateEvent(event) method (called by subscriber):**
    - Filter: only process events where `event.type === "container_state"`
    - Extract `stackId` and `stackStatus` from the event

    **ERROR handling:**
    - If `stackStatus === "ERROR"` and `!active.has("error")`:
      - Cancel any pending UNHEALTHY timer for this stack (ERROR supersedes UNHEALTHY)
      - Add "error" to active incidents for this stack
      - Fetch stack displayName from repo for the notification message
      - Call `notificationService.notify({ type: "stack_error", stackId, subject: "Stack error: {displayName}", message: "Stack {displayName} entered ERROR state at {ISO timestamp}\n\nThis notification will not repeat until the stack recovers." })`
      - If `getRecentLogs` is provided, append recent log lines to the message

    **UNHEALTHY handling:**
    - If `stackStatus === "UNHEALTHY"` and `!active.has("unhealthy")` and no pending timer:
      - Start a 2-minute (120_000ms) `setTimeout`
      - In the callback: check `activeIncidents` again (may have been cleared by recovery), then add "unhealthy" to active set and call `notificationService.notify({ type: "stack_unhealthy", stackId, subject: "Stack unhealthy: {displayName}", message: "Stack {displayName} has been UNHEALTHY for over 2 minutes..." })`
      - Store timer in `unhealthyTimers`

    **Recovery handling:**
    - If `stackStatus` is "RUNNING", "HEALTHY", or "STOPPED":
      - Cancel any pending UNHEALTHY timer for this stack
      - Delete this stack from `activeIncidents` (clears both "error" and "unhealthy")

    **stop() method:**
    - Call `unsubscribe?.()`
    - Clear all UNHEALTHY timers via `clearTimeout`
    - Clear both Maps

    **Singleton export:**
    Use lazy dynamic import pattern (same as StatePoller) to avoid pulling db.ts into test module graph:
    ```typescript
    let _watcher: NotificationWatcher | null = null
    export function getNotificationWatcher(): NotificationWatcher { ... }
    export const notificationWatcher = { start: () => getNotificationWatcher().start(), stop: () => _watcher?.stop() }
    ```
    Or simpler: if tests use constructor injection (they do), export the class and create a lazy singleton.

        settingsRepo: { getMany(keys: string[]): Promise<Record<string, string>>; get(key: string): Promise<string | null> }

    **Class implementation:**
    ```typescript
    export class DiskChecker {
        private cronTask: cron.ScheduledTask | null = null
        private readonly statfs: typeof import("node:fs/promises").statfs
        private readonly monitorPath: string

        constructor(private readonly deps: DiskCheckerDeps) {
            this.statfs = deps.statfs ?? (await import("node:fs/promises")).statfs
            this.monitorPath = deps.monitorPath ?? "/var/lib/docker"
        }
    }
    ```
    Actually, since constructor can't be async, use a different approach:
    - Store `deps.statfs` if provided (for testing)
    - In `check()`, if no statfs override, dynamically import `node:fs/promises` and call `statfs`

    **start() method:**
    - Run `this.check()` immediately (fire-and-forget with `void`)
    - Schedule cron: `cron.schedule("0 0 * * *", () => void this.check())` — runs daily at midnight

    **stop() method:**
    - `this.cronTask?.stop()`

    **check() method:**
    1. Read toggle: `const settings = await this.deps.settingsRepo.getMany(["notify.diskWarning", "disk.thresholdPercent", "disk.thresholdBytes"])`
    2. If `settings["notify.diskWarning"] === "false"`, return early
    3. Parse thresholds: `thresholdPercent = Number(settings["disk.thresholdPercent"] ?? "10")`, `thresholdBytes = BigInt(settings["disk.thresholdBytes"] ?? "2147483648")`
    4. Call `statfs(this.monitorPath)`:
       ```typescript
       const stats = await this.statfs(this.monitorPath)
       const freeBytes = BigInt(stats.bavail) * BigInt(stats.bsize)
       const totalBytes = BigInt(stats.blocks) * BigInt(stats.bsize)
       const freePercent = Number(freeBytes * 100n / totalBytes)
       ```
    5. Determine triggers: `belowPercent = freePercent < thresholdPercent`, `belowBytes = freeBytes < thresholdBytes`, `triggered = belowPercent || belowBytes`
    6. Read alert state: `const lastAlert = await this.deps.notificationRepo.findLastDiskAlert()`
    7. If `triggered && (!lastAlert || !lastAlert.active)`:
       - Set alert active: `await this.deps.notificationRepo.setDiskAlertActive(true)`
       - Build message with: mount point, current free space (bytes + percent), which threshold was crossed (per CONTEXT.md email content spec)
       - Call `notificationService.notify({ type: "disk_warning", subject: "Disk space warning", message })`
    8. If `!triggered && lastAlert?.active`:
       - Clear alert: `await this.deps.notificationRepo.setDiskAlertActive(false)`
    9. Wrap statfs call in try/catch — log error, do not crash job (per Pitfall 5 in RESEARCH.md)
