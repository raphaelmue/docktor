<objective>
Fix Windows path handling in backup service and clarify that repository path setting only applies to remote backends (SFTP/S3), not local backups.

Purpose: Prevent malformed backup paths on Windows (e.g., `C:\C\Users\...`) and eliminate confusion around repository path configuration when backups are always stored in `<stackPath>/backups`.
Output: Corrected path construction logic and improved Settings UI clarity.
</objective>

Current implementation stores backups in `<stackPath>/backups` directory for all stacks. The repository path setting was originally intended for a global shared repository but is now only meaningful for remote backends (SFTP/S3).

**Problem 1:** Line 536 in backup-service.ts uses `path.join(stackPath, "backups")` which creates malformed paths on Windows when stackPath contains a drive letter (e.g., `C:\Users\...` becomes `C:\C\Users\...`).

**Problem 2:** The "Repository Path" field in Settings is shown for `repoType: "local"` but is never used (backups always go to stack-local directory). This confuses users and the validation schema requires it unnecessarily.

**Root cause:** `path.join()` on Windows can double drive letter prefixes when joining absolute paths. Should use `path.resolve()` instead.
</context>

Line 536: Replace `path.join(stackPath, "backups")` with `path.resolve(stackPath, "backups")`.

Reasoning: `path.resolve()` always returns an absolute path and properly handles drive letters on Windows. When given an absolute path as the first argument, it correctly appends the second argument without doubling the drive letter.

Before:
```typescript
if (stackPath) {
    base.RESTIC_REPOSITORY = path.join(stackPath, "backups")
}
```

After:
```typescript
if (stackPath) {
    base.RESTIC_REPOSITORY = path.resolve(stackPath, "backups")
}
```
