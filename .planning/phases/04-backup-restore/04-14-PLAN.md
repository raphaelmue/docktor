## Root Cause

When BackupService.runBackup() calls `resticExecutor.run(["backup", ...buildBackupArgs(stackPath, stackId)])`, the backup operation includes the entire `stackPath` directory. The restic repository is stored at `${stackPath}/backups` (as configured in BackupService.buildEnv() line 536). This means:

1. First backup: Creates snapshot of stackPath, including the (initially empty) `/backups` subdirectory
2. Second backup: Creates snapshot of stackPath, including `/backups` which now contains the first snapshot's data
3. Restic detects the repository data as part of the backup content, identifies it as a duplicate, and overwrites/corrupts the previous snapshot
4. Retention policy (forget --prune) operates on corrupted snapshot data, pruning incorrectly

**Current exclusions in buildBackupArgs():**
- `${stackPath}/logs` — excluded (correct)
- `${stackPath}/backups` — **NOT excluded** (bug)

The restic CLI already excludes `${stackPath}/logs` to prevent log noise in backups. The same exclusion pattern must be applied to `/backups` to prevent circular backup.

  <name>Task 2: Add /backups exclusion to buildBackupArgs()</name>
  <files>server/src/infrastructure/restic-executor.ts</files>
  <action>
Modify the `buildBackupArgs()` method (line 123) to exclude both `/logs` and `/backups` directories:

**Current implementation (line 124):**
```typescript
return [stackPath, "--exclude", `${stackPath}/logs`, "--tag", stackId, "--json"];
```

**Fixed implementation:**
```typescript
return [
    stackPath,
    "--exclude", `${stackPath}/logs`,
    "--exclude", `${stackPath}/backups`,
    "--tag", stackId,
    "--json"
];
```

**Rationale:**
- Restic accepts multiple `--exclude` flags (one per path to exclude)
- Order matters: exclusions must come AFTER the source path but BEFORE `--tag` and `--json` flags
- Pattern `${stackPath}/backups` matches the directory where buildEnv() places the RESTIC_REPOSITORY (backup-service.ts line 536: `path.resolve(stackPath, "backups")`)

**Why this fixes the issue:**
Excluding `${stackPath}/backups` prevents restic from reading the repository data as backup source content. Without this exclusion:
1. Backup includes repository files → restic sees its own metadata
2. Restic content deduplication identifies repository files as "duplicate" data
3. Snapshot is corrupted or overwritten instead of being created as a new, independent snapshot
4. Retention policy operates on corrupted data, pruning incorrectly

With this exclusion:
1. Backup includes only stack content (compose files, volumes, env) — NOT the repository directory
2. Each backup creates a distinct snapshot with unique content hash
3. Snapshots accumulate normally according to retention policy (keepDaily, keepWeekly, keepMonthly)
4. Repository integrity is maintained
