<objective>
Stop the backup detail page from showing a stale story after the stream ends.

Purpose: the page fetches its Backup record exactly once, on mount, and never again. If a user opens it while the backup is IN_PROGRESS and watches it finish, `backup.status` stays `"IN_PROGRESS"` in React state until a manual reload. `displayLines` therefore stays bound to the streamed lines instead of the persisted ones, the status badge keeps claiming the backup is running, and the destructive alert — gated on `backup.status === "FAILED"` — never renders. That is the most likely reading of UAT Test 12's "still no logs, only the error message". Separately, the hook collapses "the backup finished and it failed" and "the SSE connection dropped" into one `error` value, so nothing downstream can tell them apart.

Output: A stream status that names four distinct outcomes, a one-shot resync that pulls the final record when the stream reaches any of the terminal three, and an Output empty state that admits when a failed backup captured nothing.
</objective>
