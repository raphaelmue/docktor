**Problem:** Lines 251 and 257 in `restoreSnapshot()` call restic with invalid flags `--no-op-stop` and `--no-op-redeploy`. These are not valid restic commands and cause restore to fail.

**Root cause analysis:** The restore flow needs to:
1. Stop the stack containers
2. Restore files from snapshot
3. Restart the stack containers

These operations should use the DockerExecutor (for stack stop/start) and ResticExecutor (only for restore), not fake restic commands.

**Fix:** The restore operation should delegate to StackService for stop/start operations. However, BackupService doesn't have a reference to StackService (circular dependency). The correct pattern is to use the DockerExecutor directly, which BackupService can accept via constructor DI.

Since this is a quick fix and the restoration logic needs proper orchestration (which may need `/gsd:research-phase` for compose down/up with volume preservation), the immediate fix is to:

**Remove the invalid restic calls entirely:**

Delete lines 250-251:
```typescript
// Stop the stack before restoring (docker compose down equivalent)
await this.resticExecutor.run(["--no-op-stop"], env, onLine)
```

Delete lines 256-257:
```typescript
// Redeploy the stack
await this.resticExecutor.run(["--no-op-redeploy"], env, onLine)
```

Keep only the valid restic restore command at line 254:
```typescript
// Restore snapshot to /
await this.resticExecutor.run(["restore", snapshotId, "--target", "/"], env, onLine)
```

**Add a comment explaining the limitation:**
```typescript
// TODO: Wrap restore with docker compose down/up
// Currently only restores files; user must manually restart stack
// Requires DockerExecutor DI or StackService orchestration to avoid manual steps
```

This allows restore to complete successfully (files restored) without invalid commands. The container restart can be handled manually or in a future enhancement.

**Alternative (if docker compose integration exists):** If BackupService already has access to a docker executor or stack service through this.filesystem or another injected dependency, use spawn() directly to run `docker compose -f ${composePath} down` and `docker compose -f ${composePath} up -d` with proper error handling. Check constructor parameters and see if any existing dependency provides docker compose access.

Upon inspection, BackupService has no docker compose integration. Use the TODO approach above — remove invalid commands, document limitation.
