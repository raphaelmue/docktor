## Color

Pre-populated from `client/src/index.css`. This phase uses the established neutral/shadcn palette — no new colors introduced. All values are CSS variables resolved at runtime (supports light and dark mode).

| Role | CSS Variable | Light Value | Dark Value | Usage |
|------|-------------|-------------|------------|-------|
| Dominant (60%) | `--background` | `oklch(1 0 0)` (white) | `oklch(0.145 0 0)` (near-black) | Page background, surfaces |
| Secondary (30%) | `--card` / `--sidebar` | `oklch(1 0 0)` / `oklch(0.985 0 0)` | `oklch(0.205 0 0)` | Cards, sidebar nav, settings panels |
| Accent (10%) | `--primary` | `oklch(0.205 0 0)` (near-black) | `oklch(0.922 0 0)` (near-white) | Primary button fill, active tab indicator, focus ring |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` (red) | `oklch(0.704 0.191 22.216)` (red) | Delete action in dropdown, Restore confirm button in dialog |
| Muted | `--muted` / `--muted-foreground` | `oklch(0.97 0 0)` / `oklch(0.556 0 0)` | `oklch(0.269 0 0)` / `oklch(0.708 0 0)` | Skeleton loaders, empty state text, disabled button states |

**Accent reserved for:**
- Primary button (`variant="default"`) — Deploy, Save Settings, Confirm Restore (inside the typed-confirm dialog only)
- Active/selected tab indicator underline
- Focus ring on interactive form fields

**Destructive reserved for:**
- Delete action text inside the stack actions dropdown menu
- The Restore button inside the typed-name confirmation `AlertDialog` (this is the only confirm-to-unlock destructive CTA)

**Status semantic colors** (established pattern from `ServiceStatusBadge` in `[id].tsx` — carry forward unchanged):

| Status | Background | Text |
|--------|-----------|------|
| BACKING_UP / IN_PROGRESS | `bg-blue-100 text-blue-800` / dark: `bg-blue-900 text-blue-200` | Inline badge |
| COMPLETED | `bg-green-100 text-green-800` / dark: `bg-green-900 text-green-200` | Inline badge |
| FAILED / ERROR | `bg-red-100 text-red-800` / dark: `bg-red-900 text-red-200` | Inline badge |
| RESTORING | `bg-yellow-100 text-yellow-800` / dark: `bg-yellow-900 text-yellow-200` | Inline badge |
| SCHEDULED trigger | `bg-muted text-muted-foreground` | Inline badge |
| MANUAL trigger | `bg-muted text-muted-foreground` | Inline badge |

**Warning color** (BCK-07 absolute-path volume warning):
- Use `Alert` component with `variant="default"` (not destructive) — an amber/warning tone is not in the design system; use the default `Alert` with a `AlertTriangle` lucide icon for visual salience. Do not introduce new color tokens.

## Page & Section Layouts

### Settings Page — Backup Tab

Layout: `Tabs` with three triggers — `General | Notifications | Backup`.

The Backup tab contains two `Card` components stacked vertically with `space-y-6`:

**Repository card:**
```
CardHeader: "Backup Repository"
CardContent:
  - Select: "Repository type" (Local / SFTP / S3-compatible)
  - [Conditional, shown when Local]: Input "Repository path"
  - [Conditional, shown when SFTP]: Input "Host", Input "Username", Textarea "Private key (PEM)"
  - [Conditional, shown when S3]: Input "Endpoint URL", Input "Bucket name", Input "Access key ID", Input "Secret access key" (type=password)
  - Input "Restic password" (type=password) — always shown regardless of type
  - Alert (if restic binary not found): "restic is not installed on this host. Install restic >= 0.17.0 to enable backups."
CardFooter: Button "Save repository settings" (primary), Badge showing restic version if available
```

Conditional field reveal: controlled by `repoType` state value from the Select. Fields appear/disappear inline via conditional rendering — no accordion, no page reload.

**Defaults card:**
```
CardHeader: "Default Backup Settings"
CardContent:
  - Input "Default schedule" (placeholder: "0 3 * * *")
    - Below input: text-xs text-muted-foreground showing human-readable preview ("Next run: tomorrow at 03:00")
    - Validation error shown inline if cron expression is invalid
  - Row with three Inputs side by side (grid-cols-3):
    - Input "Keep daily" (number, placeholder: "7")
    - Input "Keep weekly" (number, placeholder: "4")
    - Input "Keep monthly" (number, placeholder: "12")
CardFooter: Button "Save defaults" (primary)
```

## Interaction Contracts

### Backup Now (manual trigger)
1. User clicks "Backup Now" in Backup Configuration card or stack actions dropdown.
2. `POST /api/stacks/:id/backup` — server returns `202 { backupId }` immediately.
3. Client fires `toast.success("Backup started", { action: { label: "View progress", onClick: navigate("/stacks/:id/backups/:backupId") } })`.
4. Backup Now button becomes disabled with label "Backup in progress…" (stack status transitions to BACKING_UP via SSE).
5. User navigates to detail page — SSE stream shows live lines.
6. On completion: status badge updates, toast if page is not active.

### Restore flow
1. User clicks "Restore" on snapshot row.
2. `RestoreConfirmDialog` opens — user reads what will happen.
3. User types stack name exactly — "Restore" button enables.
4. User confirms — `POST /api/stacks/:id/restore` with `{ snapshotId }`.
5. Toast: "Restore started" with link to detail page.
6. Stack transitions to RESTORING (SSE). Restore button in Snapshots section remains visible in ERROR state for retry.

### Settings save pattern
All settings cards in the Backup tab use the established pattern from the General and Notifications settings cards:
- Optimistic save with `toast.promise()` wrapping the API call.
- Field-level validation errors mapped from `ApiError.fields` to react-hook-form errors.
- No full-page reload on save.

### Snapshots refresh
- Snapshots section loads on tab open (`useEffect` on `activeTab === "backups"`).
- "Refresh" button re-fetches `GET /api/stacks/:id/snapshots`.
- While stack is BACKING_UP or RESTORING, section shows the locked state `Alert` instead of the table; auto-refreshes when stack status returns to a non-transitional state via SSE.

## Accessibility Contract

- All icon-only buttons must have `aria-label`: e.g. `aria-label="Stack actions"` on the kebab DropdownMenu trigger, `aria-label="Refresh snapshots"` on the Refresh button.
- The typed-name `Input` in the restore confirm dialog must have `aria-label="Confirm stack name"` and be auto-focused when the dialog opens.
- `AlertDialog` uses Radix UI's built-in focus trap and `aria-modal`.
- Status badges rendered as `<span>` must not rely on color alone — the text label always accompanies the color (e.g. "IN PROGRESS", "COMPLETED", "FAILED").
- Disabled "Backup in progress…" button must remain visible (not hidden) so users understand why the action is unavailable — established in CONTEXT.md.
- Log output `ScrollArea` should be `aria-live="polite"` while streaming, switched to `aria-live="off"` once complete.
