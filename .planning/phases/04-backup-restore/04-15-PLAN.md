<objective>
Make a failed backup say why it failed, and stop a half-started backup from wedging the stack.

Purpose: UAT Test 12 still reports "no logs, only the error message" for a FAILED backup, and UAT Test 22 still reports a scheduled-backup crash. Three defects sit behind those two reports. First, the live SSE branch ends the stream with a payload that omits `status`, so the client's `data.status === "COMPLETED"` check is false for every live-watched backup — successes included — and every one of them is reported as an error. Second, a backup that dies before restic writes a byte (a bad pre-hook, a missing binary, an unreachable repository) persists an empty `logLines` array, so the Output pane has nothing to show and the user is left with only the alert text. Third, when the fire-and-forget dependency fetch in either the route or the scheduler fails, both paths only log: the Backup row stays IN_PROGRESS forever and the stack stays in BACKING_UP forever, which `assertTransition` then refuses to move out of — no deploy, no stop, no further backup.

Output: A terminal status carried on the `done` event, a guaranteed diagnostic log line on every failure, and one shared `abortBackup()` path that both the manual route and the scheduler use to end a backup that never started.
</objective>
