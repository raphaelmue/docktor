<objective>
Make the reverse proxy a thing Docktor owns: a real, protected `Stack` row deployed
through the same pipeline every user stack uses, configured from Settings, and
impossible to stop, restart or delete by accident.

Purpose: PRXY-02's "auto-deploys and manages" and PRXY-03's "configurable in
Settings" both land here, and so does D-12's protected-stack concept — the one piece
of Phase 6 that has no precedent anywhere in the codebase and that later plans (the
Proxy tab's gating empty state, the wizard step, the cert poller's certs path) all
depend on.

Output: server-side `isProtected` enforcement, a dashboard visibility setting, proxy
settings getters/setters, a compose renderer for the two proxy containers, a
`deployProxyStack()` with a real host-port pre-flight, and four proxy settings
endpoints.
</objective>

<planner_decisions>
- **RESEARCH.md Open Question 2 — RESOLVED: the proxy stack's Compose and Environment
  tabs stay editable.** "Protected" means exactly the three destructive lifecycle
  actions D-12 names (stop, restart, delete). A user who edits the proxy compose file
  by hand is using a deliberate escape hatch, consistent with the project's YAML-first
  decision; taking it away would make Docktor the only way to fix a proxy stack
  Docktor itself broke. Recorded as an accepted risk in the threat register.
- **RESEARCH.md Open Question 3 — RESOLVED: `isProtected` blocks `deleteStack()`
  unconditionally,** so `DockerExecutor.down()`'s `-v` flag can never reach the proxy
  stack's certs volume through the normal action path. No separate uninstall flow is
  in scope (CONTEXT.md deferred nothing, meaning it is out of scope, not queued).
- **Empty ACME email — RESOLVED: allowed.** D-09 makes the email explicitly
  non-blocking, so `renderProxyStackCompose` omits `DEFAULT_EMAIL` entirely when the
  setting is empty rather than emitting an empty value. Certificate issuance still
  works without a registration address; the Settings card says so.
- **Changing the ACME email — RESOLVED: re-render and redeploy.** The value is inlined
  into the proxy compose file rather than interpolated from a `.env`, so
  `PUT /api/settings/proxy` re-renders and redeploys when the email changed and the
  proxy stack already exists. One source of truth for the running configuration, and
  no second env-file write path to keep in sync.
</planner_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `PUT /api/settings/proxy` | an untrusted `acmeEmail` string crosses here and is written into a compose file |
| browser -> `POST /api/stacks/:id/{stop,restart,delete}` | a direct API call that bypasses any client-side button disabling |
| Docktor -> generated proxy compose file -> host Docker daemon | Docktor authors a file that mounts the host Docker socket into two containers |
| host Docker daemon -> `listContainers` | untrusted container names and port bindings are read back for the D-11 pre-flight |
