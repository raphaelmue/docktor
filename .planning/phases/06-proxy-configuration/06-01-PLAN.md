<planner_decisions>
Discretion points CONTEXT.md left open, resolved here so every later plan inherits
one answer. These are decisions, not suggestions — do not re-litigate them mid-task.

- **D-03 network wiring — RESOLVED: one shared external network named exactly `docktor_proxy`.**
  The proxy stack's own compose file owns the definition and pins the literal name
  (`networks: {docktor_proxy: {name: docktor_proxy}}`) so Compose creates it on that
  stack's first deploy without a project-name prefix. Every target stack references
  it as `networks: {docktor_proxy: {external: true}}`. `assignDomain()` refuses with
  a `BadRequestError` when the `docktor-proxy` stack row does not exist, so a target
  compose file can never reference a network that was never created (Pitfall 2).
- **D-04 UI/API scope — RESOLVED: minimal.** `domain`, `internalPort`, `tlsEnabled`
  only. No `HTTPS_METHOD`, `HSTS`, `VIRTUAL_PROTO`, `client_max_body_size` or
  per-vhost config knobs (see `COVERAGE.md` for the full reasoned opt-out list).
- **D-06 dormant fields — RESOLVED: drop both.** `npmProxyHostId` has no meaning
  under D-01 and `isPublic` has no nginx-proxy equivalent. Dead columns are design
  debt (CLAUDE.md "Remove dead code"). The table has zero rows in every environment
  (zero references exist in application code today), so the drop is safe.
- **Shared internal port per service — RESOLVED.** nginx-proxy allows exactly one
  `VIRTUAL_PORT` per container, so all domains for one service share one internal
  port. A second assign for the same service with a *different* `internalPort` is a
  `BadRequestError` naming the port already in use, not a silent overwrite of the
  first domain's port.
- **Reversibility gates — RESOLVED: no `checkpoint:decision` is inserted anywhere in
  this phase, deliberately.** `REVERSIBILITY_GATES` is on, and two CONTEXT.md decisions
  carry a rating above `reversible`: D-01 (`one-way`) and D-12 (`costly`). D-12's rating
  calls for a flag, not a gate, and it is flagged on 06-03 Task 1. D-01 is a genuine
  one-way door, but CONTEXT.md records the human choosing this exact option after
  weighing it against the NPM REST integration — the door is already walked through, and
  the reversibility reference's own anti-pattern list forbids re-asking a decision the
  phase context already records. The one-way reversibility element stays on
  Task 1 so the signal survives in the plan; `verify plan-structure` will emit a warning
  about the missing preceding checkpoint, and that warning is expected and correct here.
- **Cert status storage — RESOLVED: three new `ProxyConfig` columns**
  (`certStatus` defaulting to `"pending"`, `certMessage`, `certCheckedAt`), typed as
  `String`/`String?`/`DateTime?` rather than a Prisma enum. A generated Prisma enum
  would have to be imported by `jobs/proxy-cert-poller.ts`, and this project has
  already been bitten by that in unit tests (STATE.md records StatePoller's
  `TRANSITIONAL_STATES` falling back to a plain string Set precisely to avoid importing
  missing prisma enums in the test environment). The closed set lives in
  `@docktor/shared` as `certStatusSchema`
  instead. This also resolves the UI-SPEC's one `⚠ unresolved` item: a row that the
  poller has not yet reported on is literally `"pending"` in the database, so the
  badge shows "Cert pending" and no fourth "Checking…" state is introduced.
</planner_decisions>

<assumption_delta_decision>
Detector fired: `{kind: "optional", term: "optional"}` on "offered as an optional
First-Run Wizard step". Re-reading the phase scope surfaces a stronger, adjacent
transition the detector's `optional` cue is a proxy for: **D-08 turns a service's
single domain into a set of domains.**

- **Primary noun:** the `(stackId, serviceName)` **domain set** — not an individual
  domain, and not a single `ProxyConfig` row.
- **Decision:** `promote`. The compose write path is defined over the whole set: it
  re-reads *every* `ProxyConfig` row for the `(stackId, serviceName)` pair and
  renders one comma-joined `VIRTUAL_HOST` / `LETSENCRYPT_HOST` value. There is no
  single-domain write path to add alongside it, even in this tracer where only one
  row exists — a single-domain fast path is exactly the singular assumption D-08
  removes, and re-introducing it silently is RESEARCH.md Pitfall 1.
- **Invariant test (accepted):** the editor unit test in Task 1 asserts that two
  rows for one service produce **one** `VIRTUAL_HOST` key with two comma-joined
  values, never two env-var keys. That test goes red the instant a future phase
  reintroduces a per-domain write.
- The wizard-step optionality itself is `no-change`: the proxy stack stays an
  ordinary `Stack` row whether the wizard step ran or was skipped; nothing about the
  identity model depends on when it was deployed.
</assumption_delta_decision>
