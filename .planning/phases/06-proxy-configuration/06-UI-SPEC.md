## Typography

Matches the project's existing (undeclared-token, Tailwind-default) type scale — no new sizes are introduced by this phase. Extracted from observed usage across `settings.tsx`, `backup-config-card.tsx`, `[id].tsx`, collapsed to exactly 2 weights per the design contract's max:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 (Tailwind default `leading-normal` for `text-sm`) |
| Label | 14px (`text-sm`, `FormLabel`/`Label`) | 600 (semibold) | 1.5 |
| Heading (Card title) | 16px (`CardTitle`, ~`text-base`) | 600 (semibold) | 1.2 |
| Caption / helper text | 12px (`text-xs`) | 400 (regular) | 1.5 |

Only two weights are used across this phase's UI: 400 (Body, Caption/helper text) and 600 (Label, Heading). shadcn's `Label`/`FormLabel` primitives ship with a default `font-medium` (500) class — for Phase 6's new UI, override this to `font-semibold` (600) on every `Label`/`FormLabel` instance so Label matches Heading exactly and no third weight value (500) is introduced. Do not use `font-medium` anywhere in this phase's new components.

No `text-lg`/`text-xl`/`text-2xl` sizes are needed for Phase 6 UI — the Proxy tab and Settings card are form-and-table surfaces, not marketing/display surfaces. Do not introduce a `Display` size.

## Color

Uses the project's existing shadcn CSS-variable palette (`client/src/index.css` — oklch tokens, light/dark pairs). No new color tokens are introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `var(--foreground)` | Page background, card content text |
| Secondary (30%) | `var(--card)`, `var(--secondary)`, `var(--muted)` | Card surfaces, table rows, muted helper text (`text-muted-foreground`) |
| Accent (10%) | `var(--primary)` (default `Button` variant) | Reserved for: the "Assign Domain" / "Save configuration" primary submit button; the "Deploy Proxy Stack" wizard-step primary CTA; the active `TabsTrigger` state (existing Tabs styling, unchanged) |
| Destructive | `var(--destructive)` | Reserved for: "Remove domain" action, cert-issuance "failed" badge/alert, D-11 port-conflict failure alert |

Additional semantic (non-token, Tailwind-utility) colors already established by this codebase for warning-severity states that are neither pure "info" nor "destructive" — reuse these exact classes, do not invent new ones:
- **Warning (amber/yellow):** `bg-yellow-100 text-yellow-800 border-yellow-200 dark:bg-yellow-900 dark:text-yellow-200 dark:border-yellow-800` — reserved for: D-13's "host port already published" warning, cert-issuance "pending" badge/status.
- **Success (green):** `text-green-600` (light) — reserved for: cert-issuance "issued"/success status text, matching the existing Deployments-table `Success` cell styling in `[id].tsx`.

Accent reserved for: primary submit/deploy buttons and the active tab indicator only — never for table rows, badges (badges use `default`/`secondary`/`destructive`/`outline` Badge variants plus the warning/success utility classes above, not raw `--accent`), or card borders.

## Visual Focal Point

The Proxy tab's primary visual anchor is the domain list `Table` (populated state) or the "No domains configured" empty state card (empty state) — not the assign-domain form. The form is a secondary, always-visible input area below/beside the table; the table (or its empty-state substitute) is what the user scans first to answer "what domains are already routed here," and where cert-status badges live to answer "is this domain secured."
