<objective>
Close the feedback loop D-05 exists for: after a user assigns a domain there is no
synchronous API to fail against, so without this plan a stuck or failed certificate is
invisible and the product reads as broken.

Purpose: turn certificate issuance from a silent background hope into three observable
states — pending, issued, failed — persisted on the `ProxyConfig` row and pushed to
every open tab over the SSE stream the app already runs.

Output: a `proxy_cert_status` member on the `StateEvent` union, a bounded log-tail
primitive on `DockerodeClient`, a `StatePoller`-shaped `ProxyCertPoller` registered in
the jobs registry, and a `useProxyStatus` hook on the client.
</objective>

<planner_decisions>
- **D-05 detection mechanism — RESOLVED: certificate-file presence first, acme-companion
  log tail only to distinguish `failed` from `pending`.** File presence is a cheap,
  deterministic positive signal; the log tail exists solely to answer "is this stuck for
  a reason?" and never to establish success. This is the direct implementation of
  RESEARCH.md Pitfall 5's requirement that a genuinely-pending first issuance (no cert
  file yet, no errors) must not be reported as a failure.
- **TLS-disabled rows — RESOLVED: skipped entirely.** A `ProxyConfig` with
  `tlsEnabled: false` never requests a certificate, so the poller leaves its
  `certStatus` at the schema default and the UI renders no certificate badge for it.
  No fourth status value is introduced (see 06-01's `<planner_decisions>` for why the
  set is exactly pending/issued/failed).
</planner_decisions>

  <behavior>
    `DockerodeClient.getLogTail(containerId, tail)`:
    - Resolves the last `tail` lines of the container's combined stdout/stderr as a single string, with the stream NOT following (it terminates on its own).
    - Resolves an empty string when the container does not exist, rather than throwing.

    `ProxyCertPoller.reconcile()`:
    - Reads every `ProxyConfig` row and ignores rows with `tlsEnabled: false`.
    - For each remaining row, reports `issued` when `{certsDir}/{domain}.crt` or `{certsDir}/{domain}/fullchain.pem` exists.
    - Reports `failed` with the matching line as `certMessage` when no certificate file exists and the acme-companion log tail contains a line mentioning the domain and matching an error indicator.
    - Reports `pending` when no certificate file exists and no matching error line does.
    - Persists a row's status through `updateCertStatus` and publishes `{type: "proxy_cert_status", proxyConfigId, stackId, domain, status, message}` ONLY when the computed status differs from the row's stored `certStatus`; an unchanged row triggers neither a write nor a publish.
    - When reading the certs directory throws (missing directory, permission denied), leaves every row untouched, publishes nothing, and logs once.
    - Reads the acme-companion log tail at most once per reconcile, and not at all when every TLS-enabled row already has a certificate file.
    - Never opens a `.key` file — a test asserts the set of paths passed to the filesystem collaborator contains no path ending in `.key`.

    `ProxyCertPoller.start()` / `stop()`:
    - `start()` schedules the 60s cron; a throwing `reconcile` is caught inside the callback and logged, and the task keeps running.
    - `stop()` stops and clears the task and is safe to call twice.
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| acme-companion container logs -> Docktor -> `certMessage` -> browser | third-party container output becomes stored data and then rendered UI text |
| proxy stack certs bind mount -> Docktor filesystem reads | files written by another container's UID are probed by the Docktor process |
| `StateBroadcaster` -> `/api/events` SSE -> every authenticated browser tab | a new event member is broadcast to all subscribers, not scoped per stack |

## STRIDE Threat Register (ASVS L1, blocking on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-20 | Information Disclosure | certificate private key material under the certs bind mount | high | mitigate | the poller establishes file *presence* only, never reads file contents, and never constructs a path ending in `.key` — asserted by a unit test over the paths passed to the filesystem port |
| T-06-21 | Information Disclosure | acme-companion log lines stored in `certMessage` and rendered in the UI | medium | mitigate | only the single line matching the row's own domain is stored and it is length-trimmed; React escapes it on render, and the UI-SPEC puts it in a scrollable monospace block rather than interpolating it into markup |
| T-06-22 | Denial of Service | log tail fetched per row instead of per reconcile | medium | mitigate | at most one `getLogTail` call per reconcile, and none at all when every TLS-enabled row already has a certificate — asserted by a unit test |
| T-06-23 | Denial of Service | SSE flooding from a poller that publishes every tick | medium | mitigate | publish only on a status change; a steady state produces zero events, asserted by a unit test |
| T-06-24 | Spoofing | `proxy_cert_status` broadcast to every authenticated tab regardless of stack | low | accept | matches the existing behaviour of every other `StateEvent` member on this stream, and Docktor is single-user by design (REQUIREMENTS.md puts RBAC/multi-user out of scope); the event carries no secret |
| T-06-25 | Tampering | an unreadable certs directory flipping healthy rows to failed | high | mitigate | a directory-level read error aborts the whole reconcile with every stored status untouched, asserted by a unit test — the failure mode this would otherwise create is a UI that declares working certificates broken |
</threat_model>
